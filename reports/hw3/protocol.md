# Протокол ДЗ 3

Анализируем E3 из ДЗ 2 при прежней конфигурации LightGBM и предобработке. Исходное разбиение состоит из пяти стратифицированных фолдов с seed 42. Зафиксированные параметры проверок, порог и диапазоны ошибок хранятся в [конфигурации ДЗ 3](../../configs/hw3.yaml).

Скрипт сверяет SHA-256 данных и состав фолдов с манифестом ДЗ 2. Для сохранённого файла с OOF-прогнозами E3 он проверяет SHA-256, ID, фактические классы и номера фолдов. При запуске без сохранённых прогнозов скрипт заново обучает E3 на каждом исходном фолде. В обоих случаях ROC-AUC и AP каждого исходного фолда должны совпасть с ДЗ 2 с абсолютным допуском 0,000001.

Разбор ошибок и срезов использует только исходные OOF-прогнозы. Для каждого примера сравниваем долю поездок с той же парой оценок кресла и развлечений среди ошибок его диапазона и всех верных прогнозов с тем же ответом, типом поездки и классом обслуживания. Для крайнего FN дополнительно проверяем оценку онлайн-посадки. Эта проверка появилась при разборе результата, поэтому носит разведочный характер. Агрегированные таблицы идут в отчёт. Файл с исходными ID выбранных примеров и полные OOF-прогнозы сохраняются локально в каталоге запуска.

Проверка разбиения меняет только seed разбиения. Проверка размера обучения использует вложенные стратифицированные подвыборки исходной обучающей части; состав валидационной части фиксирован. В `robustness_folds.csv` записаны метрики, размеры обучающих и проверочных частей, SHA-256 списков ID и парные разницы ROC-AUC для сокращённой выборки. Парные разницы считаем только внутри исходных фолдов.

Обычный запуск сохраняет новый отчёт в `outputs/hw3/report/`. Опубликованные таблицы и графики лежат рядом с этим протоколом. Для проверки публикации сравните новый отчёт с сохранёнными результатами и выполните все ячейки ноутбука.
